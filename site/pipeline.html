What does this system do?

LLMs often say wrong things when they explain chess moves; they can even propose moves that are not legal. We make the LLM explain a move only through facts that a chess engine and a rules library have verified. To decide which verified facts form a good explanation, the LLM guides a search over those facts. This is the method of our supervisors' TESSERA paper (LLM-guided Monte Carlo tree search over a knowledge graph), moved from drugs and diseases to chess.

What we research: do explanations built this way become more correct and more useful than explanations written by an LLM directly, or by an LLM that is just told the engine's answer?

5 MCTS with the LLM: choosing what to say MCTS LLM

  

    
1. Select
Pick the most promising path so far.

    
2. Expand LLM prior
LLM scores the possible next facts (0–10).

    
3. Evaluate LLM evaluator
LLM rates the chain (0–3). Goal = +1, dead end = −1.

    
4. Update
Add the score to every step of the path.

  

  
The LLM only gives scores; the MCTS formula decides where to search next.
